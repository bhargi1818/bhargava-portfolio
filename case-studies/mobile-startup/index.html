MARBLE / 02 / MOBILE

A lighter launch, without a rushed experience.

Performance work starts with understanding what the product is trying to preserve. Marble’s deliberate splash dwell was a design choice; oversized photographic assets were not.

RESULT / DESIGN OUTCOME68.9 → 6.2 MB

Bundled splash imagery

TOOLS & CONCEPTS

React Native · Image encoding · Startup state

CONTRIBUTION

Product and technical direction, agent-assisted implementation, review, and release decisions.

Devin contributed implementation. This case study describes the project work and its documented checks, not sole manual authorship.

The problem

Nine splash photographs were stored as large PNGs. Together they accounted for 68.9 MB. The transition also lacked a readiness signal for the splash image itself, so timing alone could trigger a fade before the image had drawn.

The decision

The images were re-encoded as appropriately sized JPEGs. The splash retained its intentional minimum dwell and waited for both destination readiness and image settlement. An image error also settled the state, avoiding a screen that could wait forever.

What was checked

The recorded splash directory shrank from 68.91 MB to 6.19 MB—about 91%. The change included visual comparisons and tests for the minimum duration, delayed image loading, authentication resolution, navigation, and image failure.

The tradeoff

These are asset-size measurements, not measured cold-start improvements or the final App Store download size. The approximately two-second minimum display time was intentionally retained. Compression was judged against the intended device display, not file size alone.

Separate deliberate product pacing from unnecessary technical cost.
