From brittle scraping to a structured pipeline.

The useful part of an AI feature is the complete workflow around the model: reliable input, structured output, understandable progress, and reviewable uncertainty.

CONTRIBUTION

Product and technical direction, agent-assisted implementation, review, and release decisions.

Devin contributed implementation. This case study describes the project work and its documented checks, not sole manual authorship.

The problem

Recipe import depended on extracting information from third-party social pages. That retrieval step was brittle, and long-running media processing was a poor fit for a single synchronous request.

The decision

The redesigned flow accepted an administrator’s media and caption upload, queued an import job, extracted audio for transcription, and passed the available content into an LLM. Normalization translated the output into the application’s recipe structure before nutrition enrichment and draft creation.

What was checked

The implementation record documents job tracking, a polling endpoint, temporary-upload cleanup, and a four-tier enrichment cascade: local data, USDA, branded-food data, then explicitly identified model estimates. It also records 138 passing test suites and a staging checklist for real-media validation.

The tradeoff

A model estimate is not a verified nutrition fact. Estimated ingredients were identified for review. The original change record still called for end-to-end testing with real uploads; a passing unit suite alone does not establish extraction accuracy or nutritional accuracy.

Design around uncertainty instead of hiding it behind a confident model response.
